Command
Handler ^WzGSa1tF

O Command Handler é a primeira camada na trilha de interação e recebe o nome do comando e seus parâmetros.

Ele faz a validação a nível de request (payload é válido? comando utilizado existe? todos os parâmetros necessários estão presentes?)

O Handler então solicita ao Command Repository pelo comando e chama seu Execute()
 ^7mQl5i7c

Command
(abstract) ^isUj7G9I

O command faz validação a nível de domínio (a tag usada é válida? número de usuários sorteados é válido?). O command também executa a ação de fato, através de uma função "Execute() error".

Cada comando deve ser uma instância de Command, implementando a função de acordo ^NOR8kclT

Command Repository ^v1hauxQv

Command Repository separa o Handler dos Command, sendo responsável por armazenar os comandos em memória no momento da inicialização do bot.

O Command Handler deve solicitar um Command para o Repository a partir do nome do comando ^ZxXtG6jx

Discord
Adapter ^HfyybbQS

O Discord Adapter é responsável por traduzir a resposta da camada de domínio (Command) para um formato que a Arikawa entenda, deixando pronto para retornar no Handler. Por exemplo: o Command retorna apenas uma resposta em texto e um objeto de erro. O Adapter converte essa mensagem de texto para *api.InteractionResponseData e devolve para o Handler ^yp81fWTs
